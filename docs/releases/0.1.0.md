# hfproxy 0.1.0

A production-hardening release. hfproxy stays a self-hosted, private caching proxy for the Hugging Face Hub backed by PostgreSQL and S3-compatible storage; this version makes it safer to run, easier to operate, and available in seven languages.

## Highlights

- **Console in 7 languages**: English (default), French, Spanish, German, Portuguese, Simplified Chinese and Japanese. Pick the language on the sign-in page or in the header; dates and numbers follow it.
- **Resilient upstream access**: retries with backoff, a circuit breaker, stale-if-error answers from the cache when the Hub is down, and a metadata cache.
- **Cache control**: total size limit with least-recently-used eviction, pins (by repository, commit, branch or tag) that eviction never touches, and a cluster-wide lock so several replicas never fill the same file twice. Interrupted downloads resume from the last stored block.
- **Identity**: LDAP accounts keep a stable identity (entryUUID/objectGUID), disabled directory accounts are refused, optional LDAP group synchronisation, and a shared, Postgres-backed login rate limiter.
- **Security**: a Content-Security-Policy without `unsafe-inline` (per-response nonce), stricter response headers, key derivation (HKDF) for tokens, sessions and saved settings, rotation of the session secret without invalidating existing data, and no default secrets in the Compose files.
- **Operations**: Helm chart, distroless non-root image pinned by digest, Prometheus alert rules, `hfproxy config show --source`, and settings that can be pinned to the environment (`HFPROXY_LOCKED_SETTINGS`).
- **Quality**: chaos tests (Hub, object store and database failures), an opt-in load test, a nightly workflow, staticcheck, gosec, vulnerability scanning, an image scan and a reproducible-build check in CI.

## Upgrading

Database migrations are applied automatically at start-up and follow the expand/contract rule, so the previous version keeps working while a rolling update is in progress. Take a database backup first, as for any upgrade.

Behaviour changes to check before upgrading:

- **`/metrics` on the public port now requires an operator login.** Scrape the dedicated metrics address (`HFPROXY_METRICS_ADDR`) instead.
- **Outbound ports are restricted**: the Hub must be reachable on 443, on port 80 of a loopback address, or on the host and port of the configured `HFPROXY_HF_BASE_URL`. Private certificate authorities are read from `SSL_CERT_DIR`.
- **The container image is distroless and runs as non-root, with no shell.** Use `hfproxy healthcheck` for health checks; the provided Compose files and chart already do.
- **Docker Compose no longer ships default secrets.** Set `HFPROXY_SESSION_SECRET` and the database and S3 credentials yourself; `hfproxy config validate` rejects the old published development values on a public deployment.
- **Go module path** is now `github.com/hfproxy/hfproxy`.
- The first administrator is still created with the CLI (`hfproxy admin create-user`).

## New settings

`HFPROXY_AUTH_CACHE_TTL`, `HFPROXY_CACHE_FILL_CONCURRENCY`, `HFPROXY_CACHE_INVENTORY_REFRESH`, `HFPROXY_CACHE_MAX_TOTAL_SIZE`, `HFPROXY_DATABASE_MAX_CONNS`, `HFPROXY_DOWNLOAD_LOG_QUEUE`, `HFPROXY_LDAP_GROUP_SYNC`, `HFPROXY_LDAP_GROUP_BASE_DN`, `HFPROXY_LDAP_GROUP_FILTER`, `HFPROXY_LOCKED_SETTINGS`, `HFPROXY_STAGING_MIN_FREE_BYTES`, `HFPROXY_UPSTREAM_BREAKER_THRESHOLD` and `HFPROXY_UPSTREAM_BREAKER_COOLDOWN`. See the README and `docs/operations.md`.

## Fixed

- A cache fill streamed to a client was aborted when the client hung up after the last byte, so small files such as `config.json` were never cached and the download stayed "in progress". Fills are now detached from the client connection, and downloads left in progress for 12 hours are closed as abandoned.
- `/metrics` was readable anonymously on the public port.
- The AWS SDK printed a DEBUG line on stderr for every cache hit.
- A Hub URL with a non-standard port could not be used.
- The user name recorded for a failed sign-in was not length-limited.

## Known limitations

- The Helm chart is linted and rendered in CI but has not been installed on a real cluster yet.
- Not tested against the real Hub with multi-gigabyte files; the load test uses files of a few tens of MiB.
- Xet/CAS transfers, uploads and repository write operations are not supported.
- Download rate limiting is not implemented; only sign-ins are rate limited.
- API error messages and the server-rendered `/login` page are in English only.
- A revoked token can still be accepted for up to `HFPROXY_AUTH_CACHE_TTL` (5 s by default) by another replica.

See `docs/audit-production-2026-10.md` for the full readiness assessment.
